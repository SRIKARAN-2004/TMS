# Database migrations

This project previously had no migration tool at all - the schema only
ever existed via `Base.metadata.create_all()` at app startup, which
creates tables that don't exist yet but never alters existing ones. Any
schema change (like the ones in this round of fixes) had to be applied by
hand. Alembic is now set up under `backend/migrations/`.

## If you're setting up a brand new, empty database

Nothing special to do. `create_all()` still runs at app startup and will
create every table with the current shape. You can optionally run:

```bash
cd backend
alembic stamp head
```

to mark Alembic as up to date, so future `alembic upgrade head` calls
don't try to re-create tables that already exist.

## If you already have a database from before this change

Your tables already match `0001_baseline` (it's a reconstruction of the
schema as it was before this round of fixes). Don't run it for real - just
mark it as already applied, then apply the real new changes in `0002`:

```bash
cd backend
alembic stamp 0001_baseline
alembic upgrade head
```

`0002_security_and_workflow` adds:
- `Time_Logs.status`, `Time_Logs.rejection_reason` (approval workflow)
- `Time_Logs.created_at`, `Time_Logs.updated_at`
- `Projects.created_at`, `Projects.updated_at`
- `Revoked_Tokens` table (JWT logout revocation)
- `Audit_Log` table (delete trail for time logs/projects)

`0005_soft_delete_and_task_timestamps` adds:
- `Time_Logs.is_deleted` (default false) - an employee removing their own
  pending entry now soft-deletes it (hidden everywhere, row kept for
  audit) instead of a hard delete. Admin/manager deletes are unaffected.
- `Tasks.created_at` (default now) - powers the "Assigned On" column on
  the Tasks screens, most visibly the employee's own read-only Tasks
  page, which shows exactly when a manager assigned each task.

## Note on accuracy

`0001_baseline` was hand-written from the original model files, not
autogenerated against a live database (this environment has no DB access).
If your actual schema drifted from the models at some point, diff it
against `0001_baseline.py` before stamping. Going forward, run
`alembic revision --autogenerate -m "..."` for new changes instead of
editing models directly - that's the entire point of adding this now.
